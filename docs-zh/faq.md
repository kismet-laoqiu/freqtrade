# Freqtrade 常见问题

## 支持的市场

Freqtrade 支持现货交易，以及一些选定交易所的（隔离）期货交易。请参考[文档首页](index.md#支持的期货交易所实验性)获取最新的支持交易所列表。

### 我的机器人可以开空头头寸吗？

Freqtrade 可以在期货市场开空头头寸。
这需要策略为此而制作 - 并在配置中设置 `"trading_mode": "futures"`。
请确保首先阅读[相关文档页面](leverage.md)。

在现货市场中，您在某些情况下可以使用杠杆现货代币，这些代币反映反向对（例如 BTCUP/USD、BTCDOWN/USD、ETHBULL/USD、ETHBEAR/USD...），可以与 Freqtrade 交易。

### 我的机器人可以交易期权或期货吗？

选定交易所支持期货交易。请参考[文档首页](index.md#支持的期货交易所实验性)获取最新的支持交易所列表。

## 初学者提示和技巧

* 当您使用策略和超参数优化文件时，您应该使用适当的代码编辑器，如 VSCode 或 PyCharm。好的代码编辑器将提供语法高亮以及行号，使查找语法错误变得容易（很可能在启动期间由 Freqtrade 指出）。

## Freqtrade 常见问题

### freqtrade 可以在同一交易对上并行开多个头寸吗？

不可以。Freqtrade 一次只会在每个交易对上开一个头寸。
但是，您可以使用 [`adjust_trade_position()` 回调](strategy-callbacks.md#adjust-trade-position) 来调整开放头寸。

回测在 `--eps` 中提供了此选项 - 但这只是为了突出显示"隐藏"信号，在实盘中不起作用。

### 机器人不启动

使用 `freqtrade trade --config config.json` 运行机器人显示输出 `freqtrade: command not found`。

这可能由以下原因引起：

* 虚拟环境未激活。
  * 运行 `source .venv/bin/activate` 激活虚拟环境。
* 安装未成功完成。
  * 请检查[安装文档](installation.md)。

### 机器人启动，但处于停止模式

确保在您的 config.json 中将 `initial_state` 配置选项设置为 `"running"`

### 我已经等了 5 分钟，为什么机器人还没有进行任何交易？

* 根据入场策略、白名单币种数量、市场情况等，可能需要数小时或数天才能找到好的交易入场位置。要有耐心！

* 回测会告诉您大致期望多少交易 - 但这不能保证它们会在时间上均匀分布 - 所以您可能在一天内有 20 笔交易，而在一周的其余时间内为 0。

* 这可能是由于配置错误。最好检查日志，它们通常会告诉您机器人是否只是没有获得买入信号（仅心跳消息），或者是否有问题（日志中的错误/异常）。

### 我已经进行了 12 笔交易，为什么我的总利润是负数？

我理解您的失望，但不幸的是 12 笔交易还不足以说明什么。如果您运行回测，您可以看到当前算法确实让您处于盈利状态，但那是在数千笔交易之后，即使在那里，您也会在您交易了数十次甚至数百次的特定币种上遭受损失。我们当然不断努力改进机器人，但它_始终_是一场赌博，应该让您在月度基础上获得适度的胜利，但您不能从几笔交易中说出太多。

### 我想更改配置。我可以在不杀死机器人的情况下做到这一点吗？

可以。您可以编辑您的配置并使用 `/reload_config` 命令重新加载配置。机器人将停止，重新加载配置和策略，并使用新配置和策略重新启动。

### 为什么我的机器人不卖掉它买的所有东西？

这被称为"币种灰尘"，可能在所有交易所发生。
这是因为许多交易所从"接收货币"中扣除费用 - 所以您买了 100 COIN - 但您只得到 99.9 COIN。
由于 COIN 以完整批量大小（1COIN 步长）交易，您不能卖出 0.9 COIN（或 99.9 COIN）- 但您需要向下舍入到 99 COIN。

这不是机器人问题，在手动交易时也会发生。

虽然 freqtrade 可以处理这个问题（它会卖出 99 COIN），但费用通常低于最小可交易批量大小（您只能交易完整的 COIN，而不是 0.9 COIN）。
将灰尘（0.9 COIN）留在交易所通常是有意义的，因为下次 freqtrade 购买 COIN 时，它会消耗剩余的小余额，这次卖出它购买的所有东西，因此慢慢减少灰尘余额（尽管它很可能永远不会达到确切的 0）。

在可能的情况下（例如在 binance 上），使用交易所的专用费用货币将解决这个问题。
在 binance 上，在您的账户中有 BNB 并在您的个人资料中启用"用 BNB 支付费用"就足够了。您的 BNB 余额将慢慢下降（因为它用于支付费用）- 但您将不再遇到灰尘（Freqtrade 将在利润计算中包括费用）。
其他交易所不提供这样的可能性，这只是您必须接受或转移到不同交易所的事情。

### 我向交易所存入了更多资金，但我的机器人不识别这一点

Freqtrade 将在必要时更新交易所余额（在下单之前）。
RPC 调用（Telegram 的 `/balance`，对 `/balance` 的 API 调用）最多每小时可以触发一次更新。

如果启用了 `adjust_trade_position`（并且机器人有符合头寸调整条件的开放交易）- 那么钱包将每小时刷新一次。
要强制立即更新，您可以使用 `/reload_config` - 这将重新启动机器人。

### 我想使用不完整的蜡烛图

Freqtrade 不会向策略提供不完整的蜡烛图。使用不完整的蜡烛图会导致重绘，从而导致策略出现"幽灵"买入，这些买入既无法回测，也无法在发生后验证。

使用不完整的蜡烛图是一种常见的错误，会导致看起来很棒但在实盘中表现不佳的策略。

### 我想从交易所导入我的现有交易

这是可能的，但需要一些手动工作。
请参阅[交易对象文档](trade-object.md#从交易所导入现有交易)以获取详细信息。

这是一种尽力而为的方法，并不适用于所有情况，特别是当使用 freqtrade 不支持的订单类型（OCO、冰山等）时，或者处理较旧的交易（交易所不再提供完整订单信息）时。
确切的限制将因交易所而异 - 详细信息通常记录在交易所的 API 文档中。

### 我想在同一台机器上运行多个机器人

请查看[高级设置文档页面](advanced-setup.md#运行多个-freqtrade-实例)。

### 我在启动机器人时收到"无法加载策略"

这通常意味着您的策略文件中有语法错误。
请检查错误消息以获取详细信息，并使用适当的代码编辑器（如 VSCode 或 PyCharm）来帮助识别语法错误。

### 我在日志中收到"缺失数据填充"消息

此消息只是一个警告，表明最新的蜡烛图中缺少蜡烛图。
根据交易所的不同，这可能表明该交易对在您使用的时间框架内没有交易 - 交易所只返回有成交量的蜡烛图。
在低成交量交易对上，这是相当常见的现象。

如果这发生在交易对列表中的所有交易对上，这可能表明最近的交易所停机。请检查您交易所的公共频道以获取详细信息。

无论原因如何，Freqtrade 都会用"空"蜡烛图填充这些蜡烛图，其中开盘、最高、最低和收盘价设置为前一个蜡烛图的收盘价 - 成交量为空。在图表中，这看起来像一个 `_` - 并与交易所通常表示 0 成交量蜡烛图的方式一致。

### 我收到"检测到 2 个蜡烛图之间的价格跳跃"

此消息是一个警告，表明蜡烛图的价格跳跃超过 30%。
这可能是交易对停止交易的迹象，并且发生了一些代币交换（例如 2021 年的 COCOS - 价格从 0.0000154 跳跃到 0.01621）。
此消息通常伴随["缺失数据填充"](#我在日志中收到缺失数据填充消息) - 因为此类交易对的交易通常会停止一段时间。

### 我想重置机器人的数据库

要重置机器人的数据库，您可以删除数据库（默认为 `tradesv3.sqlite` 或 `tradesv3.dryrun.sqlite`），或通过 `--db-url` 使用不同的数据库 url（例如 `sqlite:///mynewdatabase.sqlite`）。

### 我在日志中收到"交易对 xxx 的历史过时"

机器人试图告诉您它得到了一个过时的最后蜡烛图（不是最后一个完整的蜡烛图）。
因此，Freqtrade 不会为此交易对进入交易 - 因为基于旧信息进行交易通常不是所期望的。

此警告可能指向以下问题之一：

* 交易所停机 -> 检查您的交易所状态页面/博客/Twitter 动态以获取详细信息。
* 系统时间错误 -> 确保您的系统时间正确。
* 几乎不交易的交易对 -> 在交易所网页上检查交易对，查看您策略使用的时间框架。如果交易对在某些蜡烛图中没有任何成交量（通常用"成交量 0"条形图可视化，蜡烛图为"_"），则此交易对在此时间框架内没有任何交易。理想情况下应避免这些交易对，因为它们可能导致订单成交问题。
* API 问题 -> API 返回错误数据（这里只是为了完整性，在支持的交易所中不应该发生）。

### 我收到"交易所 XXX 不支持市价订单"消息并且无法运行我的策略

如消息所说，您的交易所不支持市价订单，并且您将[订单类型](configuration.md#理解-order_types)之一设置为"market"。您的策略可能是为其他交易所编写的，并为"stoploss"订单设置"market"订单，这对于大多数支持市价订单的交易所来说是正确和可取的（但对于 Gate.io 不是）。

要解决此问题，请在策略中重新定义订单类型以使用"limit"而不是"market"：

```python
order_types = {
    ...
    "stoploss": "limit",
    ...
}
```

如果订单类型在您的自定义配置而不是策略中定义，则应在配置文件中应用相同的修复。

### 我试图启动实盘机器人，但收到 API 权限错误

像 `Invalid API-key, IP, or permissions for action` 这样的错误确切地意味着它们实际所说的。
您的 API 密钥要么无效（复制/粘贴错误？检查配置中的前导/尾随空格），要么已过期，或者您运行机器人的 IP 未在交易所的 API 控制台中启用。
通常，权限"现货交易"（或您使用的交易所中的等效权限）是必需的。
期货通常必须专门启用。

### 如何在机器人日志中搜索某些内容？

在 Linux 和 macOS 上，您可以使用 `grep` 来搜索日志文件中的特定字符串。

```bash
# 搜索包含 "ERROR" 的行
grep "ERROR" user_data/logs/freqtrade.log

# 搜索特定交易对的交易
grep "BTC/USDT" user_data/logs/freqtrade.log

# 搜索买入信号
grep "enter_long" user_data/logs/freqtrade.log
```

在 Windows 上，Freqtrade 也支持 `--logfile` 选项，您可以使用 `findstr` 命令在日志中搜索感兴趣的字符串：

```cmd
type \path\to\mylogfile.log | findstr "something"
```

## 超参数优化模块

### 为什么 freqtrade 没有 GPU 支持？

首先，大多数指标库没有 GPU 支持 - 因此，对于指标计算来说，好处很少。
GPU 改进只适用于 pandas 原生计算 - 或您自己编写的计算。

GPU 只擅长处理数字（浮点运算）。
对于超参数优化，我们需要数字处理（找到下一个参数）和运行 python 代码（运行回测）。
因此，GPU 不太适合超参数优化的大部分工作。

### 为什么我的超参数优化运行这么慢？

* 使用更快的计算机（更多 CPU、更快的磁盘、更多 RAM）
* 使用更少的 CPU（如果您的磁盘很慢 - 例如 HDD）
* 减少时间范围（使用较短的 `--timerange`）
* 减少交易对数量
* 减少"时期"数量（`-e` 参数）
* 减少搜索空间（减少要优化的参数数量）

### 我应该运行多少个时期？

这取决于您的搜索空间。如果您有很多参数，您需要更多的时期。
一般来说，1000-10000 个时期是一个好的起点。

### 我的超参数优化结果不好

* 确保您的策略在回测中表现良好
* 尝试不同的损失函数
* 增加时期数量
* 检查您的搜索空间是否合理
* 考虑使用不同的优化器

Freqtrade 没有加密代币发行。

您在互联网上找到的引用 Freqtrade、FreqAI 或 freqUI 的代币发行必须被视为诈骗，试图利用 freqtrade 的受欢迎程度为他们自己的恶意收益。
