# 递归分析

本页面解释如何验证您的策略是否因某些指标的递归问题而存在不准确性。

递归公式定义序列的任何项相对于其前面的项。递归公式的一个例子是 a<sub>n</sub> = a<sub>n-1</sub> + b。

为什么这对 Freqtrade 很重要？在回测中，机器人将根据指定的时间范围获取交易对的完整数据。但在模拟/实盘运行中，机器人将受到每个交易所提供的数据量的限制。

例如，要计算一个非常基本的指标叫做 `steps`，第一行的值总是 0，而后续行的值等于前一行的值加 1。如果我使用最新的 1000 根蜡烛图来计算它，那么第一行的 `steps` 值是 0，最后一根已关闭蜡烛图的 `steps` 值是 999。

如果计算只使用最新的 500 根蜡烛图会发生什么？那么最后一根已关闭蜡烛图的 `steps` 值不是 999，而是 499。值的差异意味着您的回测结果可能与您的模拟/实盘运行结果不同。

`recursive-analysis` 命令需要历史数据可用。要了解如何获取您感兴趣的交易对和交易所的数据，
请转到文档的[数据下载](data-download.md)部分。

此命令建立在准备不同长度的数据并基于它们计算指标的基础上。
这不会回测策略本身，而只是计算指标。在计算不同启动蜡烛图值（`startup_candle_count`）的指标完成后，比较所有指定 `startup_candle_count` 的最后行的值，以查看它们与基础计算相比显示多少方差。

命令设置：

- 使用 `-p` 选项设置您想要分析的交易对。由于我们只查看指标值，使用多个交易对是多余的。最好使用价格相对较高且至少有中等波动性的交易对，如 BTC 或 ETH，以避免可能使结果不准确的舍入问题。如果命令中没有设置交易对，用于此分析的交易对是白名单中的第一个交易对。
- 建议设置长时间范围（至少 5000 根蜡烛图），以便用作基准的初始指标计算本身具有非常小或没有递归问题。例如，对于 5m 时间框架，5000 根蜡烛图的时间范围将等于 18 天。
- `--cache` 被强制为 "none" 以避免自动加载以前的指标计算。

除了递归公式检查外，此命令还仅对指标值进行简单的前瞻性偏差检查。要进行完整的前瞻性检查，请使用[前瞻性分析](lookahead-analysis.md)。

### 为什么使用奇数默认启动蜡烛图？

启动蜡烛图的默认值是奇数。当机器人从交易所的 API 获取蜡烛图数据时，最后一根蜡烛图是机器人正在检查的蜡烛图，其余数据是"启动蜡烛图"。

例如，Binance 每次 API 调用允许 1000 根蜡烛图。当机器人接收到 1000 根蜡烛图时，最后一根蜡烛图是"当前蜡烛图"，前面的 999 根蜡烛图是"启动蜡烛图"。通过将启动蜡烛图计数设置为 1000 而不是 999，机器人将尝试获取 1001 根蜡烛图。然后交易所 API 将以分页形式发送蜡烛图数据，即在 Binance API 的情况下，这将是两组 - 一组长度为 1000，另一组长度为 1。这导致机器人认为策略需要 1001 根蜡烛图的数据，因此它将下载 2000 根蜡烛图的数据，这意味着将有 1 根"当前蜡烛图"和 1999 根"启动蜡烛图"。

此外，交易所限制连续批量 API 调用的数量，例如 Binance 允许 5 次调用。在这种情况下，只能从 Binance API 下载 5000 根蜡烛图而不会达到 API 速率限制，这意味着您可以拥有的最大 `startup_candle_count` 是 4999。

请注意，此蜡烛图限制可能在将来被交易所更改，恕不另行通知。

### 命令如何工作？

- 首先使用提供的时间范围进行初始指标计算，为指标值生成基准。
- 设置基准后，它将为每个不同的启动蜡烛图计数值进行额外的运行。
- 然后命令将比较最后蜡烛图行的指标值并在表格中报告差异。

## 理解递归分析输出

这是一个输出结果表的示例，其中至少有一个指标存在递归公式问题：

```
| indicators   | 20      | 40      | 80     | 100    | 150     | 300     | 999    |
|--------------+---------+---------+--------+--------+---------+---------+--------|
| rsi_30       | nan%    | -6.025% | 0.612% | 0.828% | -0.140% | 0.000%  | 0.000% |
| rsi_14       | 24.141% | -0.876% | 0.070% | 0.007% | -0.000% | -0.000% | -      |
```

列标题表示分析中使用的不同 `startup_candle_count`。表格中的值表示计算的指标与基准值相比的方差。

`nan%` 意味着由于缺乏数据，无法计算该指标的值。在此示例中，您无法仅用 21 根蜡烛图（1 根当前蜡烛图 + 20 根启动蜡烛图）计算长度为 30 的 RSI。

用户应该按指标评估表格，以决定指定的 `startup_candle_count` 是否导致足够小的方差，使指标不会对入场和/或出场产生任何影响。

因此，追求绝对零方差（由 `-` 值显示）可能不是最佳选择，因为某些指标可能需要您使用如此长的 `startup_candle_count` 才能获得零方差。

## 注意事项

- `recursive-analysis` 只会计算和比较最后一行的指标值。输出表报告不同启动蜡烛图计数计算与原始基准计算之间的百分比差异。它是否对您的入场和出场有任何实际影响不包括在内。
- 理想情况是，尽管启动蜡烛图发生变化，指标将没有方差（或至少非常接近 0%）。实际上，EMA 等指标使用递归公式来计算指标值，因此目标不一定是零百分比方差，而是方差足够低（因此 `startup_candle_count` 足够高），使指标固有的递归不会对交易决策产生任何实际影响。
- `recursive-analysis` 只会在 `populate_indicators` 和 `@informative` 装饰器上运行计算。如果您在 `populate_entry_trend` 或 `populate_exit_trend` 中放置任何指标计算，它不会被计算。

## 使用示例

### 基本用法

```bash
# 分析策略的递归问题
freqtrade recursive-analysis --strategy MyStrategy --timerange 20230101-20231231
```

### 指定交易对

```bash
# 使用特定交易对进行分析
freqtrade recursive-analysis --strategy MyStrategy --pairs BTC/USDT --timerange 20230101-20231231
```

### 自定义启动蜡烛图数量

```bash
# 指定要测试的启动蜡烛图数量
freqtrade recursive-analysis --strategy MyStrategy --startup-candles 20 40 80 160 320 640
```

## 常见递归问题

### 1. EMA 指标

EMA（指数移动平均线）是典型的递归指标：

```python
# EMA 计算依赖于前一个值
ema_today = (price_today * multiplier) + (ema_yesterday * (1 - multiplier))
```

### 2. 累积指标

任何累积计算都可能有递归问题：

```python
# 错误：累积和没有固定窗口
dataframe['cumsum'] = dataframe['volume'].cumsum()

# 正确：使用滚动窗口
dataframe['rolling_sum'] = dataframe['volume'].rolling(20).sum()
```

### 3. 自定义递归指标

```python
# 可能有递归问题的自定义指标
def custom_indicator(dataframe):
    result = [0]  # 初始值
    for i in range(1, len(dataframe)):
        result.append(result[-1] * 0.9 + dataframe['close'].iloc[i] * 0.1)
    return result
```

## 解决递归问题

### 1. 增加启动蜡烛图数量

```python
class MyStrategy(IStrategy):
    startup_candle_count = 200  # 增加到足够的数量
```

### 2. 使用非递归替代方案

```python
# 替代 EMA 使用 SMA
dataframe['sma_20'] = dataframe['close'].rolling(20).mean()

# 或使用足够长的 EMA 预热期
dataframe['ema_20'] = ta.EMA(dataframe['close'], timeperiod=20)
```

### 3. 预计算指标

```python
def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
    # 确保有足够的数据进行预热
    if len(dataframe) < self.startup_candle_count:
        return dataframe
    
    # 计算指标
    dataframe['ema_20'] = ta.EMA(dataframe['close'], timeperiod=20)
    return dataframe
```

## 最佳实践

1. **设置足够的启动蜡烛图**：通常至少是指标周期的 3-5 倍
2. **测试不同的启动蜡烛图数量**：使用递归分析找到最佳值
3. **避免过度复杂的递归指标**：简单的指标通常更稳定
4. **定期验证**：在策略开发过程中定期运行递归分析
5. **文档记录**：记录您选择的启动蜡烛图数量的原因

## 性能考虑

- 更多的启动蜡烛图意味着更多的数据下载和存储
- 平衡准确性和性能需求
- 考虑交易所的 API 限制
- 监控内存使用情况
